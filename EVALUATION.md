# Evaluation results

Generated by `python -m evaluation.run_eval --write`. Every number here is reproducible: the suite runs against the deterministic offline planner, so it needs no API key and spends nothing.

- **planner:** offline (deterministic planner; evaluation)
- **cases:** 29
- **passed:** 29/29 (100%)
- **mean confidence:** 0.65
- **mean repair iterations:** 1.32


## Summary

All 29 cases passed. Confidence averaged 0.65 across the set, and the agent needed 1.32 attempts per request on average.


**That 100% should not be read as a strong result on its own.** The case set was written alongside the fixes it describes: eight real defects were found by running the system by hand and reading its output (a faint retrieval hit injecting invented numeric targets, a cold-start request driving the repair loop to exclude the entire catalog, and an off-domain check that rejected `my girlfriend dumped me`, among others -- the full list is in the README), and the cases that would have caught them were added as they were fixed. A suite that passes everything it was written against is a regression guard, not evidence of quality.

The load-bearing evidence is in the three experiments below, where the system is measured against configurations it was *not* tuned for -- and in the ablation it drops to a 55% pass rate.

## Experiment 2: the retrieval ablation

The same suite with the notes corpus switched off (`--no-retrieval`). This is the measurement that shows whether retrieval is load-bearing: if the pass rate were unchanged, the RAG layer would be decoration.

|---|---|---|---|
| with retrieval | 29/29 | 100% | 0.65 |

## Experiment 3: is the confidence score worth publishing

A confidence number that does not separate good runs from bad ones is not measuring anything, and publishing it would be worse than publishing nothing.

| metric | value |
|---|---|
| scored runs (refusals excluded) | 22 |
| mean confidence, thin requests | 0.35 |
| mean confidence, specified requests | 0.689 |
| thin scored below specified | True |
| --- pass/fail separation, measured on the no-retrieval runs --- |  |
| degraded runs scored | 18 |
| mean confidence, degraded runs that passed | 0.236 |
| mean confidence, degraded runs that failed | 0.188 |
| separation | 0.048 |

**Reading this honestly: the confidence score is good at one of its two jobs and weak at the other.**

It separates a thin request from a well-specified one clearly -- a gap of 0.339 between the two groups (0.35 against 0.689). That is the failure it was built to catch, and it catches it.

It is much weaker at separating runs that *failed* from runs that *passed* when both were equally under-informed: only 0.048 between them in the degraded configuration. The reason is structural -- two of the four components (retrieval strength and specificity) are near zero for every run in that configuration, so they depress the score for the passing and failing runs alike. In other words the score answers "was I told enough to do this well?" and not "did I actually get this one right?". Those are different questions, and only the first is currently measured. Narrowing that gap would need a signal the system does not yet have, such as held-out human judgements to regress against.


## What this suite does not cover

- **The live Claude path.** Every number above comes from the deterministic offline
  planner. The `ClaudeBackend` request shape is pinned by unit tests with a fake
  client (model id, schema, grounding content, refusal handling, fallback), but no
  test in this repository has called the real API. Run
  `python -m evaluation.run_eval --live` with `ANTHROPIC_API_KEY` set to produce the
  comparable table.
- **Playlist taste.** Every criterion here is a measurable property -- energy, artist repetition, running time, ordering. Whether the playlist is *good* is a human
  judgement, recorded separately in `docs/human_eval.md`.
- **Catalog scale.** 22 songs is small enough that some constraints are
  unsatisfiable in principle (there is exactly one Spanish track). The suite asserts
  the system relaxes and explains, not that it succeeds.
